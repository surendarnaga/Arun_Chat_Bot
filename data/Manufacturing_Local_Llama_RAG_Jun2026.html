Integration point: company Copilot can remain in place, but this knowledge assistant should be built as its own internal RAG service. The clean pattern is: users ask questions in a simple web UI, Teams bot or internal tool, and that tool calls your local Llama-based RAG API.

Recommended Architecture

1

Collect and classify

Separate reports, quality documents, validation findings, issue logs, recordings and know-how documents. Tag author, product, defect type, date, plant and confidentiality.

2

Extract searchable text

Use OCR for scans and Whisper for audio or video. Keep timestamps in transcripts so users can jump back to exact evidence.

3

Chunk and enrich

Split text into retrieval-sized chunks and store metadata such as source path, version, author and issue category.

4

Index for hybrid search

Use vector embeddings plus BM25 keyword search so exact part names, issue labels and people names still rank correctly.

5

Answer with local Llama

Retrieve top evidence, rerank, then ask the model to answer only from those chunks and return source citations.

6

Expose a simple internal API

Keep the serving layer simple: search, summarize and latest-document lookup. That is enough for the example questions you gave.

Suggested stack

  • Local Ollama or vLLM for Llama serving
  • Local Llama 3.1 8B Instruct for POC
  • Local BGE-M3 or Nomic Embed Text for embeddings
  • Local Qdrant or PostgreSQL plus pgvector
  • Must Hybrid search with BM25 for exact keywords
  • Must Whisper large-v3 for recordings
  • Must OCR for scanned reports

What the first release should do

  • Find reports related to a specific issue like lantern clip problems
  • Summarize cited findings for a topic like split leather validation
  • Locate the latest know-how document by a named author like Martin
  • Return file path, date, author and confidence with every answer
